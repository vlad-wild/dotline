# Батарея и сон

Замена трём функциям MyASUS: лимит зарядки, здоровье батареи, и сам
ноутбук теперь реально засыпает при закрытии крышки (раньше —
`switch-events { lid-close { ... } }` в `config.kdl` только блокировал
экран, саму машину в сон не отправлял вообще).

## Крышка и сон (`system/etc/systemd/logind.conf.d/dotline.conf`)

```
HandleLidSwitch=suspend-then-hibernate
HandleLidSwitchExternalPower=suspend
HandleLidSwitchDocked=ignore
```

Приоритет этих трёх ключей — собственный, в systemd (не наш): `Docked` >
`ExternalPower` > обычный. На столе с внешним монитором (eGPU «desk mode»
из плана) крышку можно закрыть, и ничего не произойдёт; на зарядке —
обычный сон; от батареи — «сон, потом гибернация», если сна слишком
затянулся.

## Гибернация после сна (`system/etc/systemd/sleep.conf.d/dotline.conf`)

```
HibernateDelaySec=2h
```

Это и так было значением systemd по умолчанию — выписано явно, чтобы
не зависеть от будущих смен умолчания апстрима. Ниже 5% заряда systemd
гибернирует сразу, независимо от этой задержки — тоже его встроенное
поведение, не то, что реализовано в этом рисе. Нужен **swapfile не
меньше объёма RAM** — он уже есть в `docs/install-arch.md` (32 ГиБ на
отдельном подтоме `@swap`, resume systemd ≥ 255 находит сам через
EFI-переменную).

## Лимит зарядки (`scripts/battery`)

```
dotline-battery status              заряд, лимит, здоровье батареи, циклы
dotline-battery limit <60|80|100>   установить и сохранить лимит
dotline-battery full-once           один раз до 100%, лимит вернётся сам
```

`limit`/`full-once` сами спрашивают `sudo` — полноценного polkit-помощника
(`dotline-helper` из плана, пункт 6a1) в рисе пока нет, поэтому это
не тумблер в настройках, а команда терминала. Что переприменяет лимит
после перезагрузки и выхода из сна (сам sysfs-атрибут сбрасывается на
значение прошивки при каждой загрузке):
- `dotline-battery-limit.service` — один раз при загрузке;
- `/usr/lib/systemd/system-sleep/dotline-battery` — хук, который systemd
  сам запускает вокруг каждого ухода в сон/пробуждения (подтверждённый
  контракт: `$1` = `pre`/`post`, `$2` = действие — из `systemd-sleep(8)`,
  не угадано). Реагирует только на `post`.

Оба намеренно **не вызывают сам `dotline-battery`**, а дублируют его
логику переприменения парой строк на месте — системный юнит/хук не может
знать, где лежит этот git-чекаут у конкретного пользователя.

## Что честно не проверено

Вся эта часть писалась на Windows, без доступа к настоящему ядру Linux на
этом ноутбуке. Под вопросом:
- **Имя файла батареи.** `BAT0` почти наверняка, но бывает `BAT1`,
  `BATC`, `BATT` — `dotline-battery` ищет его глобом
  (`/sys/class/power_supply/BAT*/...`), никогда не захардкожен `BAT0`.
- **Есть ли вообще `charge_control_end_threshold` на этой модели.** Нужен
  драйвер `asus-nb-wmi` (или более новый `asus-armoury` на самых свежих
  платах) — если его нет, `dotline-battery status` честно напишет «не
  поддерживается», а не соврёт про несуществующий лимит.
- **Какие значения в принципе принимаются.** У части моделей — любое целое
  1–100, у части — только шаги 60/80/100. `limit` узнаёт это по факту:
  ядро само отклоняет непонравившееся значение (ненулевой код выхода
  `tee`), и это показывается как ошибка, а не тихо проглатывается.
- Полный цикл закрытие крышки → сон → (без AC, через 2 часа) → гибернация
  → будильник/открытие крышки → сессия восстановлена — непроверяем без
  реального железа.

## Уведомления о низком заряде (`services/Status.qml`)

20% / 10% (критично) / 5% (критично) — `notify-send` через уже
существующий `NotificationServer` шелла (он и так принимает
D-Bus-уведомления от любого приложения, свои собственные ничем не
отличаются). Срабатывает один раз за разряд (не на каждый опрос раз в
5 секунд, пока уровень уже ниже порога) и перевзводится при зарядке или
возврате выше ~25%. Про звук и хаптику из плана — не делал: нет ни
подтверждённого звукового файла под рукой, ни рабочей хаптики (та
по-прежнему эксперимент, см. `docs/mouse.md`).

## Что не делал

- Автоматические правила про профиль производительности / частоту экрана
  по событию зарядки (другой кусок плана, `5b`/`PowerProfile.qml`).
- Предупреждение о перегреве — не проверен путь `hwmon` на этом железе.
- Раздельные тайм-ауты простоя для сети и для батареи (сейчас один общий
  `IdleMonitor` на 5 минут в `shell.qml`, без различения AC/батареи).
- «Полный заряд один раз» из MyASUS — это именно `full-once` выше, но
  интерфейс только из терминала, не из быстрых настроек.
