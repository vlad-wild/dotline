# Темы и шрифты

## Готовые палитры (вместо извлечения цвета из обоев)

```
dotline-theme preset list              # доступные имена
dotline-theme preset <имя> [dark|light]  # применить (по умолчанию dark)
dotline-theme preset wallpaper          # вернуться к палитре из обоев
```

Сейчас доступны: `catppuccin` (Mocha/Latte), `nord`, `gruvbox`,
`nothing-mono` (фирменный монохром+красный, он и так дефолт), `nothing-light`
(светлый вариант того же). Hex-значения взяты из официальных источников
каждого проекта (Catppuccin — его собственная таблица палитры на GitHub,
Nord — nordtheme.com, Gruvbox — исходник `gruvbox.vim`), не придуманы.
«outline» переиспользует «muted» для всех пресетов — упрощение, у
большинства исходных палитр отдельного тона под это просто нет.

**Rosé Pine, Everforest, Kanagawa из плана — ещё не добавлены**: механизм
тот же (`PALETTE_PRESETS` в `scripts/palette-post`), просто не успел
свести точные hex-значения для них в этом заходе.

## yazi и btop — через их собственные темы, не через наши шаблоны

В отличие от kitty/GTK/fuzzel/niri (красим напрямую через
`palette-templates/*.tmpl`), для yazi и btop готовая палитра просто
**выбирает уже существующую** тему/flavor вместо того, чтобы изобретать
свою — у обоих есть собственная богатая экосистема тем, которую глупо
дублировать:
- **yazi**: `~/.config/yazi/theme.toml`'s `[flavor]` — имя, под которым
  одноимённый flavor ставится через `ya pkg add
  yazi-rs/flavors:<имя>` (нужно один раз руками, подсказка печатается
  после применения пресета).
- **btop**: `color_theme` в `btop.conf` — только для `nord`/`gruvbox`,
  они уже вшиты в сам пакет btop (проверено по списку файлов пакета);
  `catppuccin` и `rose-pine` там не бандлены, поэтому для них это поле
  осознанно не трогается.
- **Это касается только режима `--preset`.** При палитре из обоев yazi и
  btop не трогаются вообще — нет разумного способа подобрать готовый
  flavor/тему под случайный акцентный цвет, извлечённый из конкретных
  обоев.

## OLED — чисто чёрный surface

`dotline-theme oled on|off` (или тумблер в быстрых настройках,
`Dotline.Theme.oledEnabled` — файл состояния, `Theme.qml` следит за ним
живьём). Форсит `surface = #000000` в тёмном режиме, работает поверх
и обоев, и любого пресета — переприменяется мгновенно к тому, что сейчас
активно.

## Что из плана не делал

- **Тёмная/светлая по закату** — зависит от города из настроек погоды,
  которой в рисе ещё нет (нет даже раздела «Погода» в настройках).
- **Единый размер текста** (Quickshell/GTK/Qt/kitty) и **выбор шрифтов
  из установленных + кнопка «Установить Nerd Font»** — зависят от окна
  настроек (6a1), которого ещё нет; делать отдельный бессвязный скрипт
  без UI смысла не было.
- **Цвета в сторонних приложениях** (Firefox/pywalfox, Telegram
  `.tdesktop-theme`, Vesktop/Discord CSS, VS Code) — каждое требует
  знания формата конкретного приложения и/или установленного плагина
  (pywalfox — расширение браузера + native messaging host), не успел
  в этом заходе; уже сделанные yazi/btop/kitty/GTK/fuzzel/niri — ровно
  то же самое направление, просто для меньшего числа приложений.

## Не проверено

Сам `palette-post --preset` прогнан на Windows через песочницу (фейковый
`HOME`/`USERPROFILE`) с реальными сравнением результата — `palette.json`,
шаблоны, `theme.toml`, подмена `color_theme` в существующем `btop.conf`
проверены численно. Не проверено на настоящем niri/Quickshell: что
`Theme.qml`/`QuickSettings.qml` действительно подхватывают `oled`-файл
живьём, и что yazi/btop реально показывают применённую тему после
перезапуска.
