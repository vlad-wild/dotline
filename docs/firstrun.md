# Мастер первого запуска

`firstrun/FirstRun.qml` открывается сам при первом старте `qs -c dotline`
— триггер такой же, как уже был у `Theme.qml`'s OLED-флага: `FileView` на
`~/.local/state/dotline/firstrun`, и `onLoadFailed` (файла ещё нет)
показывает мастер. Последний шаг пишет туда `done`, так что повторно
сам он больше не всплывает. Открыть снова в любой момент можно из
**Настройки → О системе → «Мастер первого запуска»**.

Девять шагов + «Готово»: приветствие → Wi-Fi → обои и тема → лицо →
телефон → мышь → лимит зарядки → приложения по умолчанию → главные
клавиши → готово. Любой шаг пропускается кнопкой «Пропустить» —
пропуск никак не блокирует завершение.

**Принцип**: мастер не содержит новой логики — каждый шаг просто
открывает уже существующую часть рис (быстрые настройки для Wi-Fi,
`faceauth-ui` для лица, меню телефона, `dotline-theme`/
`dotline-wallpaper`, `dotline-battery limit`, шпаргалку клавиш) или
вызывает `xdg-settings`/`xdg-mime` напрямую. Ни одного нового бэкенда
не понадобилось.

## Отклонения от плана (оба сознательные, не недосмотр)

- **«Мышь (проверка хаптики)»** — шаг просто открывает Solaar
  (`solaar --window=show`, формат флага подтверждён отдельно: `show` —
  документированное значение, не только уже использовавшийся `hide`).
  Настоящей проверки хаптики нет, потому что хаптика на Linux пока ни
  одним инструментом не настраивается программно (см. `docs/mouse.md`)
  — делать вид, что это «проверка», было бы нечестно.
- **«Интерактивный тур по клавишам»** — вместо живого отслеживания
  нажатий (потребовало бы завязки на диспетчер биндов самого niri,
  которой нет) — статичный список нескольких ключевых сочетаний + кнопка
  «Открыть полную шпаргалку» (`keys/KeysCheatSheet.qml`, уже существует).

## Приложения по умолчанию

Только **браузер** (`xdg-settings set default-web-browser
<id>.desktop`, кнопки Firefox/Brave — оба реально в `packages/apps.txt`)
и **почта** (`xdg-mime default thunderbird.desktop
x-scheme-handler/mailto`) — обе команды сверены по формату через
веб-поиск (сам `xdg-settings`/`xdg-mime`, не выдумано).

**Файлы/терминал/редактор сознательно не предлагаются**: в этом рисе
это yazi/kitty/neovim — уже открываются напрямую по `Mod+E`/`Mod+Enter`
(`config.kdl`), не через стандартный диалог «открыть файл в приложении
по умолчанию». `neovim` действительно ставит `.desktop`-файл (сверено
через веб-поиск — переименован апстримом в `org.neovim.nvim.desktop`),
но делать вид, что xdg-mime для текстовых файлов имеет смысл в
терминально-ориентированном, управляемом биндами рисе, было бы
искусственно — решение, а не недосмотр.

## Не проверено

Сам факт, что `FileView.onLoadFailed` надёжно срабатывает при первом
запуске без файла — тот же паттерн, что уже используется (и не
проверен на реальной Quickshell) в `Theme.qml`'s OLED-флаге; реальная
проверка — на ноутбуке, при первом `qs -c dotline` после `install.sh`.
