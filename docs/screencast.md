# Трансляция экрана на ТВ

Быстрые настройки (`Mod+N`, кнопка в конце меню) → «ТРАНСЛЯЦИЯ НА ТВ»
запускает `gnome-network-displays` — его собственное окно (GTK4) ищет
устройства в сети и показывает список. Один инструмент покрывает оба
типа телевизоров: по его собственному описанию он «поддерживает протоколы
Miracast и Chromecast».

## Почему это вообще должно работать под niri

`gnome-network-displays` берёт кадры экрана через обычный, не привязанный
к конкретному композитору интерфейс `org.freedesktop.portal.ScreenCast`
(проверено по его исходникам, `src/nd-screencast-portal.c`) — то есть он
не завязан на GNOME Shell/Mutter напрямую, вопреки некоторым старым
описаниям в сети. niri умеет отдавать кадры через этот портал, если за
бэкенд `ScreenCast` отвечает `xdg-desktop-portal-gnome` (это
задокументированный путь для niri — PipeWire под капотом), а не
`xdg-desktop-portal-gtk`.

Проблема в том, что оба пакета (`xdg-desktop-portal-gnome` и
`xdg-desktop-portal-gtk`) уже стоят в `packages/desktop.txt` — gnome ради
трансляции/скриншотов, gtk ради диалога выбора файла. Без явного указания,
какой backend использовать для какого интерфейса, выбор между ними не
гарантирован, и трансляция (и запись через `Win+Alt+R`, и шаринг экрана в
Zoom/Meet) может упасть с «no screencast backend». Поэтому
`dotfiles/xdg-desktop-portal/.config/xdg-desktop-portal/portals.conf`
явно закрепляет:

```
[preferred]
default=gnome;gtk
org.freedesktop.impl.portal.ScreenCast=gnome
org.freedesktop.impl.portal.Screenshot=gnome
```

Это не отдельный костыль ради кастинга на ТВ — тот же файл чинит
потенциально то же самое падение и для записи экрана, и для шаринга в
видеозвонках, которые в плане уже числятся как использующие портал.

## Какой протокол для какого ТВ

- **Chromecast / Google TV / Android TV** (значок трансляции в меню
  приложения `gnome-network-displays`): проще всего кастовать прямо из
  браузера — Brave (он же Chromium) уже умеет нативную кнопку «Трансляция»
  для вкладки/видео без всякой лишней настройки. `gnome-network-displays`
  нужен именно для трансляции **всего экрана** целиком.
- **Miracast** (обычные смарт-ТВ с «беспроводным дисплеем», то же, что
  «из коробки» умеет любой Windows-ноутбук): только через
  `gnome-network-displays`, отдельного браузерного пути нет.

## Что не проверено

Разработка идёт на Windows без доступа к Wayland/niri и без обоих типов
телевизоров под рукой — реальный прогон (список устройств находится,
трансляция стабильна, звук идёт) только на месте, в офисе. Если
`gnome-network-displays` пожалуется на отсутствующий портал даже после
`portals.conf` — проверить `busctl --user list | grep portal`, что вообще
запущен `xdg-desktop-portal-gnome`, а не только `-gtk`.
