# Scratchpad и картинка-в-картинке

## Выпадающий терминал и заметки

`Mod+\`` и `Mod+Shift+\`` — не самописный механизм на `niri msg
event-stream` + подбор рабочего стола `scratch`, как изначально
описывал план, а штатный кittens kitty **`quick-access-terminal`**:
wlr-layer-shell дропдаун, который сам умеет показываться/прятаться по
повторному вызову одной и той же команды. Проверил по докам kitty — он
создан именно для этого сценария, писать его заново смысла не было.

- `dotfiles/kitty/.config/kitty/quick-access-terminal.conf` —
  подхватывается самим kitten автоматически (`~/.config/kitty/quick-
  access-terminal.conf`, без `--config`), общий для обоих дропдаунов.
- `Mod+\`` → `kitten quick-access-terminal` — обычная оболочка.
- `Mod+Shift+\`` → `kitten quick-access-terminal --instance-group notes
  -- nvim ~/Notes/scratch.md` — второй, независимый от первого дропдаун
  (`--instance-group` даёт отдельное состояние показан/скрыт), сразу
  открывающий заметки. `mkdir -p ~/Notes` перед запуском — на случай,
  если папки ещё не существует.

## Картинка-в-картинке

Статическое правило окна (`window-rule` в `config.kdl`), без кода:

```
window-rule {
    match title="[Pp]icture.in.[Pp]icture"
    open-floating true
    default-floating-position x=16 y=16 relative-to="bottom-right"
}
```

- `open-floating`/`default-floating-position` — настоящие правила niri
  (с версии 25.01), не выдумано.
- **Совпадение по заголовку, не по app-id** — сознательно: у окна PiP в
  Chromium на Wayland **вообще нет app-id** (подтверждённый апстрим-баг
  Chromium, не ограничение niri) — правило по app-id просто никогда бы
  не сработало для Chromium/Brave. Заголовок — единственное, что
  выставляют оба браузера.
- Регекс `[Pp]icture.in.[Pp]icture` специально нестрогий к регистру и
  разделителю (`.` вместо дефиса/пробела), чтобы не зависеть от точной
  капитализации/пунктуации у каждого браузера по отдельности.

## Закрепление окна на всех рабочих столах

`Mod+Shift+P` — `niri-float-sticky -ipc toggle_sticky`. У niri в
принципе нет понятия «прилипающего» окна (открытый апстрим-тикет
niri-wm/niri#932) — это стороннее, но специально под эту задачу
написанное сообществом niri решение (демон + сокет-IPC), а не
самописный велосипед поверх `event-stream`, как в исходном тексте
плана. Пакет — `niri-float-sticky` (AUR), демон стартует через
`spawn-at-startup`.

**Важно: `Mod+Shift+P` раньше был занят профилем питания** (вместо
изначально запланированного `Mod+Ctrl+P`) — более ранняя сессия
привязала его туда по ошибке. Перевесил профиль питания на
`Mod+Ctrl+P`, как и было в исходной таблице плана, освободив
`Mod+Shift+P` под его настоящее назначение.

## Не проверено

Ничего из этого не прогонялось на реальном niri/Wayland (разработка — на
Windows). При первой проверке на ноутбуке: действительно ли kitty
`quick-access-terminal` показывается поверх всего и прячется повторным
вызовом; ловит ли правило PiP оба браузера по факту; успевает ли
`niri-float-sticky` стартовать до первого использования `Mod+Shift+P`.
